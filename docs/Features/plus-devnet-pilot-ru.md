# Mosh+: инструкция для готовых сборок

Пилот из [PR #89](https://github.com/redstone-md/mosh-flutter/pull/89), ветка
`feat/plus-devnet`. Установщики собраны из `63d814be`, версия 0.22.0.
Компилировать приложение не требуется.

## Текущее состояние, 17 октября 2026

Billing запущен на пилотном Linux-хосте как `mosh-billing-devnet.service`,
слушает только `127.0.0.1:8787` и использует постоянную SQLite. Публичный ключ
совпадает с ключом, закреплённым в обоих установщиках. Создание заказа и его
восстановление после перезапуска проверены через настоящий HTTP и Rust.

**Оплата пока заблокирована стартовым devnet SOL.** Публичный RPC-faucet вернул
HTTP 429; баланс оператора нулевой. Адрес mint подготовлен, но сам mint ещё не
создан на devnet. Успешный ответ каталога не означает готовность оплаты.
Реальная транзакция и выдача сертификата по ней пока не проверены.

| Параметр | Значение |
| --- | --- |
| Сеть | Solana Devnet |
| Продукт | Mosh+ на 30 дней, округление срока вверх до дня UTC |
| Цена | 1 тестовый токен, `1000000000` атомарных единиц |
| Адрес будущего classic SPL mint, 9 decimals | `A9giLS3dDb19DsQyn9hAa3sWP4Pcb2MW511j9TYnsRzM` |
| Получатель / оператор | `C6VKzHnLWxr6UGdRxnxzA3aVcZZ4pG6euo7MGUCFGWYr` |

Для разблокировки оператору нужно минимум 0.02 **devnet SOL** через
[Solana Faucet](https://faucet.solana.com). После пополнения оператор создаёт mint,
пополняет тестовый кошелёк и выполняет реальный платёжный прогон. Приватные ключи,
база и конфигурация находятся вне публичного репозитория.

## 1. Установить приложение

1. Войди в GitHub и скачай ZIP для своей системы:
   [Windows](https://github.com/redstone-md/mosh-flutter/actions/runs/38985706107/artifacts/12083936668)
   или [macOS, Intel и Apple Silicon](https://github.com/redstone-md/mosh-flutter/actions/runs/38985708065/artifacts/12083532577).
2. Распакуй ZIP. Закрой Mosh. В Windows запусти `mosh-0.22.0-setup.exe`,
   в macOS открой `Mosh_0.22.0_universal.dmg` и перенеси Mosh в Applications.
3. Запусти Mosh и используй свой обычный профиль. Для проверки сохранения покупки
   после перезапуска нужны те же данные приложения.

В ZIP есть SHA256-файл; хеши обоих установщиков проверены после скачивания с CI.

## 2. Подключиться к billing

Оба установщика уже настроены на `http://127.0.0.1:8787` и один публичный ключ.
Если приложение работает на другой машине, открой терминал / PowerShell и выполни:

```sh
ssh -N -L 8787:127.0.0.1:8787 USER@SERVER
```

Замени `USER@SERVER` на свой SSH-логин и адрес Linux-хоста с billing.
Оставь терминал открытым. Публичный HTTPS-сервер и пересборка для этого не нужны.

Открой в браузере `http://127.0.0.1:8787/v1/catalog`: должны совпасть сеть,
mint, получатель и атомарная цена из таблицы. Затем открой
**Настройки → Профиль → Mosh+**. Должны появиться условия оплаты.

## 3. Подготовить кошелёк после создания mint

1. Внешний мобильный кошелёк должен поддерживать Solana Pay с SPL-токенами.
   Переключи его на **Solana Devnet** вручную: QR сеть не выбирает.
2. Передай оператору публичный devnet-адрес кошелька. Оператор пополнит его
   тестовыми токенами и devnet SOL для комиссии. Приватный ключ или seed-фраза
   для этого не нужны.
3. Проверь совпадение mint и наличие тестового токена на кошельке.

## 4. Оплатить

1. В **Настройки → Профиль → Mosh+** проверь сеть, mint, получателя и цену.
2. Нажми **«Создать QR для оплаты»**. Заказ сохраняется до появления QR.
3. Отсканируй QR внешним кошельком и подтверди перевод.
4. Дождись подтверждения в devnet и надписи о сроке действия Mosh+.
   Приложение проверяет заказ примерно раз в пять секунд; финализация сети
   занимает дополнительное время. При ошибке используй обновление того же заказа.
5. Закрой и снова открой Mosh. Покупка и срок действия должны сохраниться.

Оплачивать надо именно запрос из QR: обычный перевод без его reference не
идентифицирует заказ. Активный или ожидающий заказ не заменяется новым.

## 5. Проверить бейдж

1. Включи **«Показывать мой бейдж Mosh+»**. Изначально показ выключен.
2. Для ручной проверки у собеседника используй другой Mosh-аккаунт на втором
   устройстве. Связывать эти два аккаунта как устройства одного аккаунта не нужно.
3. Проверь бейдж пользователя в DM, автора сообщений, участниках группы/канала
   и участниках организации. Название самой группы или канала бейдж не получает.
4. Выключи показ и дождись исчезновения бейджа у собеседника. Доставка доказательств
   идёт без текстовых сообщений, примерно раз в пять секунд.

Для покупки достаточно одного компьютера с Mosh и телефона с кошельком.
Независимые native-клиенты, доставка и скрытие бейджа через Moss уже проверены
автоматически с тестовым сертификатом. Проверка с сертификатом после реальной
devnet-оплаты пока ожидает пополнения.

## Что проверено и что осталось

- Пройдены серверные HTTP/SQLite/криптографические тесты, настоящий Rust bridge,
  Flutter checkout и доставка/скрытие бейджа через реальные Moss/MLS.
- Пилотный systemd-сервис создал заказ и восстановил тот же заказ после рестарта;
  запрос без bearer capability получил отказ.
- Подготовлен отдельный программный прогон реальной devnet-оплаты в приватном
  `mosh-billing`: недоплата, корректный перевод, повторная выдача, рестарты
  и проверка сертификата независимым native-получателем.
- Реальная devnet-оплата, сканирование мобильным кошельком и ручной запуск
  установщиков Windows/macOS пока не отмечены как пройденные.

Протокол и ограничения пилота описаны в [plus-devnet.md](plus-devnet.md).
