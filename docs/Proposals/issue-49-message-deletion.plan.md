# Issue #49: удаление отдельных сообщений

Статус: все 22 решения интервью и итоговый план согласованы. Пользователь разрешил реализацию, включая изменения публичных контрактов, протокола и схемы хранения.

## Согласованное поведение

- Личные чаты, группы и каналы. Текст, фото, файлы и голосовые сообщения; удаление по одному и массовое выделение.
- «Удалить у меня» для своих и полученных сообщений. Из истории исчезает вся запись. Удаление синхронизируется между активными связанными устройствами, включая подключённые позднее.
- Записи звонков и служебные события удаляются только «у меня»; состояние группы и история остальных участников сохраняются.
- «Удалить у всех» без срока. В личных чатах и каналах разрешено автору своих сообщений; в группах текущие админы могут удалить также чужие сообщения.
- Права определяются по проверенному авторству и действующим ролям. Имена отправителей и непроверенные идентификаторы канала не подтверждают права.
- После удаления «у всех» остаётся «Сообщение удалено». Для модерации: «Сообщение удалено администратором Иваном».
- До подтверждения получателем показываем «Ожидает доставки». В DM подтверждает собеседник; в группе/канале ответ одного участника означает «Запрос подтверждён», а состояние сохраняется для остальных офлайн-участников.
- Офлайн-запросы сохраняются и повторяются после подключения и перезапуска. При временной невозможности проверить роль запрос ожидает проверки.
- Потеря админом прав или выход автора из группы до принятия запроса отменяет ещё не принятое удаление «у всех». Локальное удаление сохраняется, отказ объясняется. Уже принятые удаления остаются действующими.
- Если устройство впервые получило старое удаление после потери автором прав, оно принимает запрос только при проверяемых правах или действующем подтверждении админа. Одного утверждения обычного участника недостаточно. Ранее проверенные этим устройством удаления сохраняются; ручное подтверждение или ожидание нового админа не требуется.
- Удаление ещё ни разу не отправленного сообщения отменяет его отправку. Уже отправленное сообщение требует отдельного удаления «у всех».
- В массовом выборе «Удалить у всех» доступно только если подходят все выбранные сообщения. Смешанный набор можно целиком удалить «у меня» или изменить выбор.
- В подтверждении явно указываем вариант удаления, количество сообщений и отмену ещё не отправленных сообщений.
- Удаление прекращает связанные передачи и воспроизведение. Копия в хранилище приложения очищается, когда её больше не использует другое сообщение. Внешние сохранённые копии и скриншоты остаются.
- Старая история удаляется «у меня». «У всех» доступно лишь при доказуемых правах и однозначной связи с исходным сообщением.
- Старые версии продолжают обычное общение, но не применяют новое удаление. Обновление само по себе не восстанавливает ранее утраченные доказательства авторства.
- Если старую запись нельзя точно сопоставить между своими устройствами, разрешаем удаление только на текущем с явной пометкой «Только на этом устройстве». Для однозначных записей действует обычная синхронизация.

## Изменения интерфейсов и хранения для согласования

- Команды удаления одного или нескольких сообщений с явным вариантом «у меня» / «у всех»; native-снимки возвращают доступные действия, результат и реальные статусы.
- Дополнительные доказательства автора и общего идентификатора сообщения в совместимых форматах сообщений/манифестов. У новых отправок одинаковых файлов разные идентификаторы отправки.
- Зашифрованные записи удаления, очереди доставки и данные, позволяющие сохранять историю синхронизации после удаления содержимого. Учёт ссылок на файлы для безопасной очистки.
- Аддитивные изменения форматов, bridge и схемы; перегенерация bindings. Новые зависимости и изменения Moss не планируются.

## Реализация по слоям

1. Ввести общую модель цели удаления и доказуемого авторства. Сохранить необходимые данные при приёме, отправке и импорте истории. Проверить совместимость прежних форматов.
2. Сделать атомарное локальное удаление: запись удаления, очистка содержимого, отмена неотправленных попыток и сохранение курсоров истории. Не допускать восстановления удалённого из outbox, replay, старого импорта или повторного пакета.
3. Добавить общий интерфейс удаления сообщений и массового выбора в существующее меню рядом с сообщением. Сохранить выбор текста и копирование. Использовать native-доступность действий.
4. Синхронизировать личное удаление через существующего владельца device-link и проверенный список устройств; сохранять одну точку чтения сетевого inbox.
5. Добавить аутентифицированные удаления и восстановление состояния в DM/группах/каналах. Переиспользовать владельцев транспорта, MLS-метаданные и сохранение подтверждений. Не расходовать обычные MLS-поколения на неограниченные метаданные.
6. Завершить повторную доставку, проверку потери прав, очистку файлов, обновление списка/поиска/медиа и ограничений старой истории. Обновить Architecture и ADR.

## Проверки

- Тесты публичного поведения: одиночное/массовое удаление, свои/чужие сообщения, роли, одинаковые имена, неподписанные каналы, старые данные и версии.
- Офлайн/перезапуск, сохранение до отправки, отказ хранилища, потеря подтверждения, изменение состава/ролей, повторные и переставленные пакеты, конкурентное удаление.
- История нового/вернувшегося устройства: удалённое не возвращается, текущий импорт не теряет курсор.
- Повторная отправка одинакового фото, общие файлы нескольких сообщений, поздние чанки и отмена воспроизведения/отправки.
- Реальные native/MLS-тесты и независимые процессы для разных установок; Flutter через test/support.
- Flutter analyze/test/format; Rust build/test/fmt/clippy; codegen и drift; покрытие изменённых строк не ниже 80%, веток 70% при доступном измерении.
- Atomic Conventional Commits, актуальный main, обычный PR и проверки CI. Merge отдельно по разрешению пользователя.

## Существенные ограничения

- Нет обещания отозвать внешние копии, применить удаление на старом клиенте или подтвердить получение каждым участником открытого канала.
- Нельзя восстановить доказательства автора или конкретной отправки, которые никогда не сохранялись.
- Метаданные удаления должны переживать отсутствие и возвращение участников; публикация пакета не доказывает удаление на получателе.
- Неизвестное старое удаление после смены прав может не восстановиться на пропустившем его устройстве. Пользователь выбрал сохранение сообщения вместо доверия неподтверждённому утверждению участника.
