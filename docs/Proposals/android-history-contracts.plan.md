Status: proposed; **not approved for implementation**. Scope: [IVO-141](https://linear.app/ivoxygen/issue/IVO-141),
[IVO-142](https://linear.app/ivoxygen/issue/IVO-142), [IVO-143](https://linear.app/ivoxygen/issue/IVO-143),

This document changes no runtime, wire format, dependency or database.

## Existing boundaries and limits

* [ADR 0031](../ADR/0031-linked-desktop-dm-history.md) and
  [ADR 0032](../ADR/0032-dm-offline-recovery.md): frozen source manifests,
  16-record batches, UTF-8 fragments, persisted rounds/cursors, atomic imports.
  These mechanisms currently live inside private DM, with DM-specific routing.
* [History persistence](../../mosh-core/src/conversation/history.rs) already
  shares `StoredMessage`, `HistoryTables`, manifests and replay among all kinds.
  [The import transaction](../../mosh-core/src/persistence/dm_history.rs) is
  DM-specific; generalize its implementation without changing DM packets.
* [Group live verification](../../mosh-core/src/private_group_runtime/authentication.rs)
  authenticates both Moss and MLS keys and compares the actual ciphertext
  signer. Semantic history rows retain neither that proof nor historical
  membership. A row's claimed epoch or sender label cannot replace this check.
* [MessageOrigin](../../mosh-core/src/message_deletion/origin.rs) signs content,
  occurrence ID, conversation, author and optional account ownership. It does
  **not** sign the row's time, label, MLS epoch or membership interval.
* [The group commit log](../../mosh-core/src/persistence/group_commits.rs)
  retains raw commits by epoch; append errors are logged. It is not an atomic
  archive of original committer authority, topology and admitted text.
* [ADR 0040](../ADR/0040-message-deletion.md) governs tombstones and historical
  deletion authority. History must use that policy, not invent weaker rights.

## Common recovery boundary

Extract the bounded manifest/cursor/fragment engine from DM history into the
existing shared conversation layer. Kind adapters retain authorization,
serialization, message conversion and transport. DM retains its signed primary
payloads, metadata extension and current admission rules unchanged.
No second history importer, private MLS snapshot import, new library or Moss API.

Use existing room subscriptions for channel history and group discovery only.
Group historical content, proofs and review bodies use recipient-directed
encrypted Moss packets; a group exporter key alone is readable by newcomers
and cannot enforce admission boundaries. Add a bounded single Mosh history
owner and fixed `mosh-history-v1\0` carrier prefix; the existing directed packet
callback demultiplexes it before the generic call-packet inbox. Keep that one
callback and device-link stream ownership. Reuse one node and existing
`send_to_peer` API, with no group-room fallback for content. Add `History`
variants to the channel blob and group control
envelopes for their allowed room messages. Old clients ignore new variants
and retain live messaging; they cannot serve the new recovery protocol.

### Packet and pagination contract

All lengths below are bytes unless stated. Integers are checked unsigned u64;
allocation counts must also fit the receiving platform's usize. JSON encodes
data; signatures use fixed-order JSON tuples with a versioned domain prefix,
not arbitrary object key order. Hashes are SHA-256, lowercase 64-character hex;
keys are complete 32-byte Ed25519 keys in lowercase hex, signatures 64 bytes.
IDs generated by the new protocol are 128 random bits encoded as 32 hex digits.

`HistoryFrameV1` signs `(version=1, conversation, mesh_id, channel, sender_key,
recipient_key, request_id, round, payload_b64)`, prefixed
`mosh-conversation-history-frame-v1\0`. Conversation is the existing
`channel:<normalized-name>` or `group:<group-id>`, never a display label.
Probe alone permits an absent recipient; replies and pulls name the exact key.
The frame signature proves the carrier, never the authors of its records.

| Payload | Fields / meaning |
| --- | --- |
| Probe | Fresh request ID, durable round, supported version; group known head |
| Offer | Echo request/round, frozen manifest hash, count, deletion digest; group required head and evidence capability |
| Pull | Selected offer hash, next record index, next fragment byte offset |
| Page | Same offer hash/count, exact cursor, up to 16 records or one fragment |
| EvidencePull / EvidencePage | Group only: exact next transition or authenticated public-history proof |
| Unavailable | Same request/source scope; expired export, missing record, missing evidence or unsupported history |

Each frame, including a directed carrier, must fit `MAX_PUBLISH_BYTES`
**after** all signatures, base64 and org wrappers. Reuse the existing bounded
fragment machinery; proposed fragments
carry at most 3 KiB of serialized record bytes. A record has at most 256 KiB
including proofs; larger supported protocol records require a reviewed limit
change, not unbounded assembly. Keep one partial record per active import,
one active source per conversation, at most four active conversation imports
per installation and at most 16 export snapshots per conversation.
An oversize record reports a bounded failure; it must not silently complete.

Persist the export's ordered keys and content digests before sending its first
page. Offers advertise a cached, mutation-invalidated manifest; the first Pull
freezes it or refuses that stale Offer. Store large manifests in bounded disk
pages rather than cloning full histories into every export. The manifest is a
hash over the version, conversation and complete ordered
`(occurrence_key, content_digest)` list. Ordering by original claimed send time
and occurrence key is a stable enumeration, not a globally authoritative clock
or channel order. Distinct source manifests are independent views.
On export refusal/expiry retain the recipient's imported rows and select a new
source in a new persisted round. Restart rejects earlier request IDs.

Probe at restore/reconnection and on changed authenticated peer availability;
coalesce to one outstanding request per conversation. Immediate next-page pull
follows a durable page save. Proposed idle retry: exponential 5–60 seconds with
jitter; source progress timeout 10 seconds, repeated Pull no faster than 2
seconds. These are initial protocol caps, **not accepted battery budgets**.
Service scheduling must yield to live delivery, calls and user transfers.
Public-channel offers are untrusted; cap candidates/bytes before allocation and
never initiate arbitrary peer dials from a claimed offer address.

### Record contract and original author

`HistoryRecordV1`: `(kind, occurrence_key, message_id, claimed_sent_at_ms,
claimed_label, author_key?, transport_peer?, content, origin?, history_proof?,
admin_endorsement?)`. The endorsement never replaces the origin or original
author signature; its exact binding is specified in the linked admin contract.
`content` is exactly one of Text UTF-8 bytes, AttachmentOffer (full original and
preview manifests), or ErasedTarget (proof/tombstone reference, no content).
No delivery states, read markers, outbound attempts, downloaded paths, files,
call state, invitation offers or MLS secrets are transmitted as history rows.
Attachment recovery restores an offer; it does not start a download or assert
that the holder possesses the original chunks.

Use the origin's conversation/id/full-author key for a verified occurrence.
Without an origin, legacy identity uses a separate namespace and the exact
semantic row digest; a self-claimed legacy ID must not collide with and replace
a verified record from another author. The source key is provenance, not the
dedup key: identical legacy copies from different holders still deduplicate.
Preserve exact local legacy correlations for personal erasure under ADR 0040;
do not derive authority from a legacy key. A byte-identical verified live row
and imported row become one occurrence and retain local receipt/send state.
Existing native message IDs remain action targets: reject reuse of one native
ID for conflicting occurrences/authors instead of inserting two ambiguous
rows into `MessageLog`, whose actions select by ID. For legacy rows lacking
an original ID, use a deterministic `legacy-<semantic-digest>` local ID and
retain the original correlation separately; never fabricate a MessageOrigin.

Verify the complete original MessageOrigin, including manifests, after fragment
assembly. Preserve it byte-for-byte. A channel holder may transmit old unsigned
rows, but they remain unverified and confer no shared deletion rights. A source
signature cannot upgrade their author, label or timestamp. Existing origins
verify content authorship only; time and label remain claims unless a new proof
also covers them. Reject conflicting verified content or inconsistent proofs
for the same occurrence, including a changed row timestamp; do not overwrite.

New sends may carry `HistoryContentProofV1`, an optional new envelope field:
dual Moss/MLS signatures for groups; Moss signature for channels. Its fixed
tuple signs conversation, mesh, complete author keys, occurrence ID, kind,
claimed time/label, semantic-content hash, and for groups the authenticated
MLS GroupContext hash, epoch and admission instance. Use distinct domain
`mosh-history-content-v1\0`. An admission instance is the hash of the canonical
Add/replace commit plus the admitted full MLS key; same label/account is
insufficient after rejoin. The proof is prepared before encryption and retained
beside the row. Existing MessageOrigin and its signing input are unchanged.
It proves what the author claimed, **not when the signature was created**.

## Atomic persistence, deletion and compatibility

Proposed additive encrypted tables:

| Table | Key and value |
| --- | --- |
| `conversation_recovery` | Kind/conversation plus local or export/recipient key; versioned round, request/source, manifest/count, cursor, bounded partial, highest required head, observed-source digests or frozen export |
| `conversation_occurrences` | Kind/conversation/native message ID; full occurrence key, existing history-row key and accepted content/proof digests |
| `group_history_evidence` | Group/transition or proof hash; authenticated public evidence and local acceptance, never MLS private material |

Add optional `history_evidence` to `StoredMessage` for retained origin-envelope
proof and proof classification. Table values use the existing encrypted-row
codec and existing installation DEK. No replacement store or key. Build the
derived occurrence index transactionally from existing history before admitting
recovery; contradictory pre-existing rows report an error, not arbitrary wins.
Empty tombstone rows retain their current history keys.

Generalize `commit_dm_history_import` behind `HistoryTables` plus the recovery
checkpoint key; preserve its DM entry point as an adapter. In **one redb
transaction**: validate occurrence conflicts, admit eligible deletion evidence,
apply personal/shared tombstones through `write_history_row`, save matching
live rows not yet flushed, store rows/manifests/evidence/index and next cursor.
Advance memory and visible completion only after commit. Refused writes retain
the old progress and permit exact retry. Never reset the ordinary tail writer
to its old prefix after insertion; mark the accepted suffix consistently.
Epoch transitions commit the receiver's own next MLS snapshot, authenticated
public evidence and recovery head together, then install the staged candidate.

Deletion metadata is admitted through existing current-policy checks. Sync the
source's advertised deletion journal to a verified frozen digest **before** its
content pages become visible. A changed digest restarts that prerequisite;
concurrent local deletion still wins under the same import transaction. Unknown
historical deletions by departed actors still need ADR 0040 current endorsement.
When exporting, replace a deleted member of a frozen manifest with ErasedTarget
using its original occurrence/content digest; don't remove its cursor slot or
reuse stale partial-content bytes. The tombstone must be verified before that
slot advances. A rejected deletion cannot legitimize a content omission.
A dishonest source can omit its own records/journal; no protocol promises a
complete global archive or knowledge of a deletion unavailable from every peer.

Add an optional shared `history_sync` snapshot to groups/channels, retaining
existing DM state values `waiting_for_source`, `importing`, `complete`. Include
an optional reason (`source_unavailable`, `evidence_missing`, `unsupported`,
`storage_refused`, `administrator_review_required`) without displaying internal
keys or paths. Existing conversation operations remain; the admin contract
proposes two bounded review calls. Regenerate bindings and reuse the notice.
Complete means this available, verified frozen view is durable. New sources or
known missing transitions can return it to waiting/importing. A missing proof
or unsupported holder is never silently treated as complete.

Old stores load optional fields absent. Old clients continue existing live
operations, but cannot provide history evidence they never retained. A channel
can recover their rows with honest legacy classification. For groups, lack of
historical authorization evidence requires the selected administrator
supplement where enough genuine original-author and membership evidence
exists. An absent author signature or a missing verifiable admission interval
is not manufactured by an update or a holder's page signature. Such records
remain honestly classified; this is not a strict-closing-root gap policy.

## Private-group evidence and membership boundaries

For IVO-142, require same locally pinned MLS group/context, complete current
source and recipient leaf keys, their dual-key proofs, and no known membership
gap. For org groups also require current verified organization membership.
Exchange content only over recipient-directed encrypted Moss packets. Verify
the sender's complete signed carrier and local recipient; the packet callback
sender alone is a claim, not authentication. Use dual-key SenderProof and org
authorization for group scope. Room discovery may use exporter metadata without
content. A recipient field on group-key ciphertext is routing, not isolation:
new members know that key. Directed-send refusal waits/retries; never publish
private historical content, attachment keys or review candidates to the group.
Application MLS generations and another installation's private state are not
used as a historical decryption mechanism.

Historical evidence is separate from current authorization. A retained proof
must identify the actual historical MLS signer and original semantic content;
the current forwarding member is not that author. Same-member recovery of
newly proven rows can precede membership-transition work. Once a verified
different head/membership is known, IVO-142 waits for IVO-143 evidence.

Public transition record proposal: original TLS commit bytes, prior and next
GroupContext hashes/epochs, full original signer keys, signed original
transition time and original org roster/version evidence where applicable.
No closing-root requirement is introduced. Relaying authenticates only the
carrier; authority comes from the original transition's verified prior state.
Retain the public signed Welcome admission anchor/tree reference locally at
join; do not import a holder's private snapshot or accept a self-signed foreign
tree as the trust root. Replay exact next commits into the local staged state.
For old public intervals, validate public state from the pinned admission
anchor; OpenMLS `PublicGroup` can validate public commits without leaf secrets.
An implementation must prove this traversal against the pinned 0.8.1 APIs;
it cannot substitute a current roster for missing original authorization.

Plain groups derive authority from their verified full-key admin succession;
org groups use separately retained signed org authority evidence. A signed org
roster version alone supplies no trusted creation-time cutoff: do not claim it
proves an operation preceded a later revocation. Missing historical authority,
expired packages without an approved historical-time basis, or a branch that
doesn't connect to the receiver's pinned anchor all leave recovery waiting.
Reuse ADR 0032's scoped lifetime validation only after original authority,
same-group binding and authenticated time have been verified.

Recipient entitlement is the intersection of verified admission intervals with
each record's proven interval. New admission excludes pre-admission history;
ordinary offline preserves membership; removal denies new exports; rejoin is
a new instance and cannot cover the absence interval. The holder rechecks
current membership/known revocations on **every page**, not just the initial
Offer. Do not roll back a known head to accept an older holder's claim.
All checks are relative to authenticated knowledge: an isolated stale replica
cannot know an unseen removal. Instant global revocation requires freshness
infrastructure and is not promised by an asynchronous P2P protocol.

### Selected trust policy: current-administrator supplements

The user chose authority-endorsed supplements, preserving full recovery where
authorized copies and adequate original evidence are available. A currently
verified administrator confirms a precise signed historical record and its
claimed membership interval. A holder can relay that endorsement while the
administrator is offline. The original author remains the original author.
The exact proof, approval flow, revocation and persistence boundaries are in
[the administrator contract](android-history-admin-contract.plan.md).

A removed author can sign a new row claiming an old time/epoch. Author
signatures and old member lists alone do not establish when that row existed;
[RFC 9420 §8.2](https://www.rfc-editor.org/rfc/rfc9420.html#section-8.2)
anchors Proposal/Commit history, not every application-message body. The chosen
policy trusts the current administrator's historical assertion for this gap.
It does not claim cryptographic pre-removal creation-time proof.

Do not automatically convert a valid old signature into an endorsement. An
administrator may confirm matching protected local live evidence automatically;
a disputed row without such evidence requires an explicit bounded review.
Otherwise a departed signer could obtain approval for newly backdated text.
No all-holder barrier delays membership changes; no closing-root omission
silently excludes a legitimate row that the selected admin policy admits.

## Verification before acceptance

Real independent installations: alternate holder with original author offline;
restart/failed transaction between pages; source replacement and old packet
replay; concurrent live/import same occurrence; altered author/time/content;
deleted fragments, personal tombstones and departed deletion actors; exact
offers without auto-download. Run through existing bridge on desktop/Android.

Group adversarial cases: same-membership plaintext transplantation; new member
requesting earlier rows; ordinary offline; removal/rejoin with absent interval;
forged old-time row signed **after** removal without admin confirmation;
precise approved historical supplement from an alternate offline holder;
admin demotion, stale/forked authority and replay into another admission;
unavailable original authority; no provider snapshots/private secrets exchanged.
Assert waiting rather than successful completion on every missing proof path.
Focused tests cover bounds, canonical transcripts and atomic refusal behavior;
real OpenMLS tests prove staged transition validation and post-recovery live
traffic. Admin confirmation is tested as trusted policy, not proof of time.
