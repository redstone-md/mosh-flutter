## Reproduced collector defect and correction

ETW starts before the collector establishes its measurement timestamp. The
aggregator previously admitted those earlier events into byte counts, peer
aliases and negative second buckets. The focused boundary regression checks
that an event one tick before the start changes none of the exported totals,
while an event exactly at the start remains in second zero.

[Windows run 40144534362](https://github.com/redstone-md/mosh-flutter/actions/runs/40144534362)
fails on that new regression against the unchanged aggregator. The correction
returns before any aggregation when `event.timestamp < startedAt`.
[Run 40144623878](https://github.com/redstone-md/mosh-flutter/actions/runs/40144623878)
passes the same boundary check and the full real ETW/CPU/recorder suite.
The source fix is `7ca10188` on `perf/desktop-idle-network`; the independently
tested equivalent is `0e22f750` on the measurement branch. No report schema,
Mosh binary, timing policy, dependency or Moss source changes.

The [verified collector bundle](https://github.com/redstone-md/mosh-flutter/actions/runs/40144623878/artifacts/12579769092)
contains twelve expected files. GitHub ZIP digest, both ZIP CRCs, inner checksum
and every packaged source file pass, allowing Windows line endings. Its inner
ZIP SHA-256 is
`647454de0782563afa52da916792e67bd8472a81fc3305b4ad0b9063e48aa995`.
Existing owner measurements remain analyzable; this correction needs no new
application installation and no repeat of this recording.
