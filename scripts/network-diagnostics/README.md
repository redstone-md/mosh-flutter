# Mosh: измерение сети на Windows

Переустанавливать или пересобирать Mosh не нужно.

1. Оставь Mosh запущенным. Открой чат или сверни приложение — как в момент,
   когда замечаешь большой расход сети. Во время замера не начинай звонки
   и передачу файлов.
2. Распакуй весь архив в отдельную папку и запусти **Start.cmd**.
3. Подтверди запрос Windows на права администратора. Они нужны коллектору
   для системной трассировки ETW; само приложение продолжает работать
   с обычными правами.
4. Подожди две минуты и завершение обработки. Путь к готовому
   **mosh-network-report.zip** появится в окне. Каталог по умолчанию:
   `%LOCALAPPDATA%\Mosh\Diagnostics\network-ДАТА-ВРЕМЯ`.
5. Передай только этот ZIP и укажи версию Mosh, был ли открыт чат или
   приложение было свёрнуто, а также где и в каких единицах виден расход.

В отчёте: байты выбранного процесса по секундам, TCP/UDP, отправка/приём,
отдельный loopback, анонимные номера сетевых адресатов, CPU/RAM и счётчики
потерь ETW. Содержимое сообщений, изображения и ключи не собираются.
Суммы ETW — размеры событий сетевого стека; это не точные байты Ethernet
и не только содержимое сообщений. TCP retransmit учитывается отдельно.

Сырой `private-network.etl` остаётся локально и **не входит в ZIP**.
Он содержит сетевые метаданные других процессов: не отправляй его.
После передачи ZIP каталог диагностики можно удалить целиком.
Размер ETL ограничен 128 МиБ; сессию останавливает коллектор и резервный
таймер. Если окно коллектора закрыть, таймер остановит запись не позднее
чем через 150 секунд после старта.

Если появится ошибка, отправь её текст. Ошибка проверки контрольных
пакетов означает, что достоверного замера нет. При потерях ETW отчёт
помечается `complete: false`; его суммы нельзя считать полными.

Если запущено несколько экземпляров Mosh, можно выбрать PID вручную:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Measure-MoshNetwork.ps1 -TargetProcessId 1234
```

## Запись событий самого Moss

Если сетевой расход подтверждён, а обычный `mosh.log` не объясняет его,
используй **Start-MossRecording.cmd** из этого же комплекта. Это отдельный
режим; старый `Start.cmd` запускает только измерение байтов через ETW.

1. Оставь один экземпляр Mosh запущенным и открой **Start-MossRecording.cmd**
   обычным двойным щелчком, без прав администратора.
2. По сообщению скрипта выйди из Mosh через значок в трее → **Выход / Quit**.
   Скрипт сам откроет тот же установленный EXE с диагностикой.
3. При необходимости разблокируй приложение и открой сохранённый чат.
   После появления записи скрипт покажет отсчёт **180 секунд**. Оставь
   приложение в простое, без звонков и передачи файлов.
4. После отсчёта ещё раз выйди из Mosh через трей. Держи окно скрипта
   открытым до выхода из Mosh. Скрипт сформирует **mosh-runtime-report.zip**
   и покажет путь; затем открой Mosh обычным ярлыком.
5. Передай `mosh-runtime-report.zip` только в приватную диагностическую
   переписку. В отличие от первого отчёта, он содержит сетевые метаданные:
   адреса узлов, идентификаторы тем, события соединений и снимки состояния.

Используется уже встроенная возможность `MOSH_DEBUG_RECORD_DIR`:
события и снимки каждые пять секунд, файл ограничен примерно 64 МиБ.
После отсчёта запись продолжается до выхода через трей или достижения
лимита файла. В манифесте отдельно указаны конец отсчёта и фактическое
завершение процесса; длительность включает ожидание последнего выхода.
Переменная задаётся только дочернему процессу; системное окружение,
настройки, история и ключи приложения не меняются. Принудительного
завершения процесса нет. Ожидания ручного выхода и запуска записи
ограничены пятью минутами; при ошибке следуй сообщению в окне.

Запись включает запуск сети, поэтому её начало нельзя считать стабильным
простоем. Это диагностические события и метрики, а не полный сетевой захват;
не все виды служебных пакетов представлены отдельными событиями.
